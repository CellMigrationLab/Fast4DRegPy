# Scientific and software audit — 2026-09-25

Scope: `main` at `f0e58b5` (0.4.1), end to end: source, tests, fixtures,
packaging, CI and documentation. Compared against the Fast4DReg Fiji macros
(v2.1 at `0483ace` and the June 2022 v1), the Fast4DReg/NanoJ Java plugin,
ImageJ 1.53t and NanoPyx 2.1.4.

## Method

The existing unit tests, documentation and compact fixtures were treated as
unverified. Evidence was collected three ways:

1. **Reading the reference source**: macros, Java plugin, ImageJ interpolation
   and scaling code, and NanoPyx's Cython source (recovered from the sdist).
2. **Running the original Fiji macro.** `time_estimate+apply.ijm` was run
   headless in ImageJ 1.53t with the Fast4DReg Java plugin compiled from the
   Fiji repository (`validation/fiji/`). Its drift tables and corrected stacks
   for eight settings are committed as a CI fixture.
3. **Forward-modelling the published data.** The drift added by the generator
   and the translation Fiji applied were both recovered from the archived
   images with an exact port of ImageJ's interpolation. This distinguishes
   implementation errors from reference-mapping or ground-truth errors.

Every defect below has a regression test that fails on 0.4.1.

## Findings

### Critical

**C1. Published ground truth was mis-converted in the tests.**
`tests/test_zenodo_synthetic.py`, `tests/test_zenodo_xyzt.py`.
The tests subtracted the published frame-0 drift, but `Drift_generator.ijm`
never translates frame 0; that value is noise that was never applied.
Fitting raw frame 0 to raw frame 6 gives an added displacement of
(z, y, x) = (−2.4792, −2.0125, 4.8259), which equals the published frame-6 value.
*Consequence:* expected translations were wrong by up to 0.84 px (Y), 0.77 px (Z)
and 0.18 px (X), so the "validated within 0.75 px" claim had no meaning.
*Fix:* expected translation = −published[t], with frame 0 at 0. Tolerances are
now based on measured errors (≤0.071 px on the five XY frames).

**C2. The compact XYZT test passed only because two errors cancelled.**
`tests/test_zenodo_xyzt.py`. The fixture keeps only 192 of 416 Y rows, and
the test estimated XY drift from that cropped field. Fiji estimates XY from
the full field. Fast4DRegPy gave dy = 1.219 px on the fixture against Fiji's
applied 2.003 px (a 0.78 px error), and the C1 expectation (1.17 px) happened
to match. *Fix:* XY is taken from the full-field fixture (within 0.0013 px of
Fiji), and a new test reproduces the archived Fiji frame voxel for voxel.

### High

**H1. The axial stretch biased every Z estimate.**
`estimation._scale_axial_projection`. `scipy.ndimage.zoom` samples on a
corner-aligned grid, so a displacement of d rows became d·(H−1)/(h−1) rows,
not s·d. Dividing by s then inflated Z shifts by 1.2% for the published
69-slice movie (0.18 px at 15 px of Z drift) and 3.9% for a 20-slice stack.
Against real Fiji runs, Z differed by up to 0.08 px. *Fix:* exact port of
ImageJ `FloatProcessor.resize`, verified against ImageJ output. Z now agrees
with Fiji to ≤0.001 px given the same input.

**H2. The final transform did not reproduce Fiji.** `transform.apply_drift`.
The default was a single SciPy cubic B-spline shift. Fiji uses ImageJ bicubic
translation (Catmull-Rom, no prefilter, bilinear edge rule, zero fill), first
per Z plane and then per axial plane. *Consequence:* using Fiji's own frame-6
translation, only 5.6% of voxels matched the archive (Pearson 0.9998). On a
sharp synthetic volume Pearson was 0.984. *Fix:* `interpolation="imagej"` is
the new default; SciPy splines stay available through
`interpolation="scipy"`. Result: 99.99% of archived voxels identical, maximum
difference 1 grey level.

**H3. Z was estimated from a differently interpolated XY-corrected stack.**
`estimation._estimate_sequence_shifts`. *Fix:* the Z projection is made from
an ImageJ-interpolated XY correction, whatever interpolation is chosen for the
output.

**H4. Time averaging used NanoPyx semantics, not Fiji's.**
`estimation._nanopyx_drift`. NanoPyx 2.1.4 correlates against the first
*averaged block* (NanoJ uses raw frame 1), drops a trailing partial block
(0.4.1 rejected such inputs; NanoJ keeps them), clamps the averaging window,
and interpolates block drifts with cubic `interp1d` at integer-truncated
knots. NanoJ uses ImageJ `resizeLinearly`, which places blocks at
b·(N−1)/(B−1). *Consequence:* up to 0.58 px against real Fiji with blocks of 3.
*Fix:* NanoJ semantics built from NanoPyx's `calculate_ccm` and
`GetMaxOptimizer`. Agreement with real Fiji is now ≤0.0015 px, including a
partial block.

**H5. Bounded search windows returned wrong values without warning.**
NanoPyx 2.1.4 slices an off-centre 2r window (translations −r…r−1). With r=5
it returned 3.534 px for a +3 px translation. Fiji crops a centred 2r+1
window, but its optimiser rejects peaks within 1 px of the window edge and
writes NaN or ±(r−1) into the drift table (reproduced in the Fiji fixture).
*Fix:* Fiji's centred window; a peak at the window edge raises `ValueError`
instead of Fiji's NaN or clamping. For Z the radius is in stretched axial
pixels, as in Fiji (now documented).

### Medium

**M1. "Crop output" was missing, and it changes registration, not only the
output.** Fiji crops the XY-corrected stack before building the axial
projection. That changes the Z input and the stretch factor; on the synthetic
Fiji fixture it moved Z by 0.27 px. *Fix:* `crop_output` (applied before Z
estimation, as in Fiji) and `extend_z`, with the macro's rectangle and padding
formulas exposed as `fiji_crop_bounds` and `fiji_z_padding`. Output
geometry matches Fiji. Both options are off by default; nothing is cropped
implicitly.

**M2. Estimates were not reproducible, although the docs claimed they were.**
NanoPyx 2.1.4's OpenMP reductions sum in a thread-dependent order. Its
DriftEstimator rounds to 3 decimals, so repeated runs differ by 0.001 px
whenever `OMP_NUM_THREADS > 1`. The docs claimed serial and parallel results
were bit-identical; the old tests only checked transforms and mocked
estimation. *Fix:* documented; the full-movie validation pins
`OMP_NUM_THREADS=1` and checks serial against parallel.

**M3. The sdist test suite failed.** `MANIFEST.in` pruned the XYZT fixture but
shipped its test. *Fix:* the test is excluded from the sdist. CI now builds
the sdist and wheel, checks the wheel contains no data, and runs the sdist
tests against the installed wheel.

**M4. XY and Z settings are shared.** Fiji exposes them separately, and the Z
search radius is in stretched units. *Recommended:* separate Z parameters
(`CODEX_TASKS.md` P1).

**M5. The ImageJ transform did not scale with `workers`** (found during this
audit; it never reached `main`). A per-plane Python loop serialised on the
GIL: 11 s with 4 workers against 3.4 s serially. *Fix:* stack-wise
translation, 0.45 s with 4 workers (see `performance.md`).

### Low

- **L1. CI coverage.** CI skipped Python 3.11, never tested a built
  distribution and did not lint `validation/`. Fixed.
- **L2. TIFF metadata.** `save_tiff` writes a tifffile-shaped TIFF rather than
  an ImageJ hyperstack with voxel sizes. Documented (P2).
- **L3. `backend` is nearly nominal.** NanoPyx's threaded and unthreaded
  DriftEstimator backends share the same CCM code, and `backend` only applies
  to unbounded, unaveraged estimation. Documented.
- **L4. Stale documentation.** README, `docs/data.md`,
  `docs/implementation_spec.md` and `docs/parity_audit.md` described Z parity
  as unproven or approximate and gave a wrong ground-truth convention.
  Rewritten.
- **L5. Degenerate averaging.** A time average that leaves fewer than two
  blocks made Fiji report zero drift. Now rejected.

### Checked and found consistent with Fiji

- XY and Z sign conventions and `(dz, dy, dx)` order: the NanoJ drift table
  stores the translation to apply.
- First- and previous-frame reference modes, including the cumulative sum.
- Maximum and average projections.
- Order of operations: XY estimation, XY correction, Z projection, Z
  estimation.
- Top/Left reslice orientation, and even-square centre cropping of
  rectangular projections.
- The axial stretch factor is computed from pixel geometry, `round(X/Z)`.
  Fiji does not use voxel calibration here (`Reslice ... avoid`), so
  anisotropic sampling is handled only through that factor.
- Multichannel time series (reference channel applied to all channels) and
  rejection of multi-timepoint channel registration.
- Non-finite, constant and one-slice inputs, odd and rectangular dimensions,
  and overwrite protection.
- Distribution name `fast4dregpy` and import name `fast4dreg`; wheel contents;
  installation and tests on Python 3.10–3.13.
